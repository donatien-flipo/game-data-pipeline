A Data Lakehouse pipeline and recommendation engine for video games. It ingests editorial data from IGDB, community engagement metrics from RAWG, and player behavior data from Steam, processes them through a Medallion architecture (Raw -> Formatted -> Usage) with Spark and MinIO, and serves analytics and recommendations via Elasticsearch and Kibana.

## Architecture Overview

The system runs as a multi-container Docker Compose stack:

![Big data project architecture diagram](<assets/Big data project architecture.png>)

### Data Layers (Medallion Pattern)

1. **Raw (Bronze)**: Immutable JSON files collected from external APIs and the Steam crawler (`s3a://data/raw/`).
2. **Formatted (Silver)**: Flattened, schema-enforced, and typed columnar Parquet datasets (`s3a://data/formatted/`). Timestamps are standardized to UTC, and extreme user libraries (>500 games) are filtered out to prevent data skew during joins.
3. **Usage (Gold)**:
   - `master_games`: Consolidated game catalog stored as an ACID Delta Lake table with precomputed Jaccard similarity scores across unified tags.
   - `steam_recommendations`: Player segmentation and personalized game suggestions generated by a Spark ML clustering pipeline.
4. **Serving**: Elasticsearch indices (`games_catalog`, `steam_recommendations`) powering Kibana dashboards.

## Machine Learning & Recommendation Logic

The recommendation engine combines collaborative tag vectorization with player clustering:

1. **Feature Extraction**: Player game libraries are mapped to tags, normalized via TF-IDF, and scaled (L2 norm).
2. **Clustering**: K-Means ($K=30$) groups players into behavioral cohorts based on cosine distance.
3. **Dynamic Cohort Naming**: The pipeline computes the **Lift** of each tag within each cluster relative to the global distribution:
   $$\text{Lift} = \frac{P(\text{tag} \mid \text{cluster})}{P(\text{tag})}$$
   The top distinctive tags automatically label each cluster (e.g., *Cluster 3: RTS & Tactical Fans*).
4. **Scoring & Filtering**:
   - Computes an implicit affinity score based on playtime over global average: $\log(1 + \text{playtime} / \text{avg\char`_playtime})$.
   - Applies cluster preference weighting while penalizing ubiquitous titles:
     $\text{Score} = \frac{\text{cluster\char`_score}^{1.2}}{\ln(1 + \text{global\char`_score})}$
   - Filters out already-owned games and ubiquitous titles (owned by >20% of users) to output top-10 recommendations per player.

## Quickstart

### Prerequisites

- Docker & Docker Compose
- 8GB+ RAM allocated to Docker

### 1. Configuration

Copy the sample environment file and set your API keys:

```bash
cp .env.example .env
```

Set the required values in `.env`:
- `IGDB_CLIENT_ID` & `IGDB_CLIENT_SECRET`: Twitch/IGDB developer credentials.
- `RAWG_API_KEY`: RAWG API token.
- `STEAM_API_KEY`: Steam Web API key.
- `SEED_STEAM_ID`: A public 64-bit Steam ID to seed the crawler.

### 2. Start Services

```bash
docker compose up -d --build
```

Web interfaces will be accessible at:
- **Airflow UI**: [http://localhost:8080](http://localhost:8080) (`admin` / `admin`)
- **MinIO Console**: [http://localhost:9001](http://localhost:9001) (`admin` / `password123`)
- **Kibana**: [http://localhost:5601](http://localhost:5601)
- **Elasticsearch**: [http://localhost:9200](http://localhost:9200)
- **Spark Master UI**: [http://localhost:8888](http://localhost:8888)

## Running the Pipelines

1. **Initial Historical Load (`bulk_pipeline`)**:
   Trigger `bulk_pipeline` in the Airflow UI to extract and format historical datasets (~30,000 games from IGDB and ~4,000 games from RAWG).

2. **Continuous Crawling (`steam_crawler_optimized`)**:
   Runs every minute, traversing Steam friend graphs via BFS to discover player profiles and store owned games into MinIO.

3. **Daily Processing & ML (`daily_pipeline`)**:
   Runs daily (or manually triggered) to:
   - Fetch 24h updates from IGDB and RAWG.
   - Consolidate new Steam player libraries with Spark Structured Streaming.
   - Merge sources into the `master_games` Delta table and recompute Jaccard similarities.
   - Retrain the K-Means player clustering model and generate recommendations.
   - Upsert updated records into Elasticsearch indices.

## Kibana Dashboards

Two data views are set up in Kibana:
- **Audience & Cohort Analysis (`steam_recommendations`)**: Displays player distribution across the 30 clusters, cluster profiles identified by Lift analysis, and top recommended titles per cluster.
- **Game Metadata & Similarities (`games_catalog`)**: Detailed view of individual titles showing cross-source ratings (IGDB, RAWG, Metacritic), community engagement, and side-by-side comparison between editorial similar games and calculated Jaccard neighbors.
